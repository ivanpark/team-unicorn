출처와 지위
사용자 제공 Unicorn-1 화면의 5 units × 7회/초 = 35 units를 기준으로 삼았다.
다중 다리 기본값은 현재 대화의 예시 보폭 [5,2,3,7,11,13], 요청빈도 [7,1,1,1,1,1]이다.
이것이 소수 라벨이 물리적 보폭을 정한다는 발견을 의미하지는 않는다.
추가한 관리비용·위상·관리자 모형은 검증용 신규 가정이며 실제 측정값이 아니다.
이 실험은 정수 산술 및 작업 대기열 모형이다. 생체역학이나 실제 푸리에
파동의 위상 간섭, 전체 Team Unicorn HQ의 탄생·귀환 모형은 구현하지 않았다.

모형
k개의 다리. 다리 i의 동작당 거리 d_i는 양의 정수, 요청빈도 f_i는 양수다.
각 요청 j(0부터 시작)의 발생 시점은 (j + phi_i)/f_i이며 0 < phi_i <= 1.
정렬 시작: 모든 phi_i=1.
분산 시작: 첫 다리는 phi_1=1; 나머지 i=2..k는 phi_i=(i-1)/k.
대기 중에도 다음 요청은 예정대로 계속 발생한다.
요청당 관리시간 h = lambda*(k-1).
shared: 한 관리자가 발생 순으로 처리하고 같은 시각에는 낮은 다리 번호가 우선.
independent: 다리별 관리자가 각 요청을 처리.
완료 시점까지의 각 동작이 +d_i를 더한다. 부분 동작은 거리로 세지 않는다.
요청은 T 이하에 발생했으나 완료가 T보다 늦으면 미완료 요청에 포함한다.
기본 실험 비용 lambda는 0/10/20/30/40/50 ms이며, 유일하게 옳은 비용이 아니다.

확인 사항
- Python Fraction 기준과 JS 계산이 432개 관측 결과에서 일치함을 확인.
  거리, 완료 건수, 미완료 건수, 직전 1초 거리, 관리비용 없는 거리 대조.
- Chromium 데스크톱·모바일 레이아웃, 프리셋 버튼, 결과 JSON 내보내기 확인.
- 브라우저 계산은 1e-9초의 부동소수점 비교 허용오차를 사용.
- d*f 반복의 모든 정수 시간 관측에서 비용 0이면 D(T)=T*D(1)을 확인.

해석
1. 고정된 정수 보폭 d와 완료 횟수 m의 곱이 소수 p이면 (d,m)은
   (1,p) 또는 (p,1)이다. 이 결과는 다중 다리 기여의 합에는 그대로 적용되지 않는다.
2. 관리비용 없이 같은 1초 패턴이 반복되면 5초와 10초의 누적거리는
   각각 1초 거리의 5배와 10배다. D(1)>1이면 둘 다 합성수다.
3. 공유 관리자에 대해 rho = h*sum(f_i)>1이면 요청률이 처리능력을 넘는다.
   이는 무한히 이어지는 고정 빈도 요청에 대한 이 모형의 병목 조건이다.
4. 30 ms, 분산 시작, 공유 관리자라는 예에서 10초 거리:
   k=1:350, k=2:365, k=3:395, k=4:465, k=5:426, k=6:375.
   같은 순서의 미완료 요청: 0,1,1,1,28,55.
   여기의 4는 보편적 최적 다리 수가 아니다. 다른 gait를 모두 최적화한 결과도 아니다.
5. 비용이 10 ms이면 6개가 10초에서 705 units로 이 여섯 구성 중 가장 크다.
   비용이 40 ms이면 3개가 395 units로 가장 크다. 관리비용 가정에 민감하다.
6. 관측시점·위상·대기 때문에 생긴 소수값은 새로운 소수 생성 원리의 증거가 아니다.
